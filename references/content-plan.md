# 两种模式共用的图文组织规则

整篇博客的默认成品是“正文图片＋穿插辅助解释图＋发布摘要”。正文统一经 HTML 排版为 3:4 PNG；HTML＋SVG 或 ImageGen 的选择只用于非正文视觉。正文内容应在图片内形成连续可读的文章。

## 图像类型

**正文页**是文章本身，用连续段落讲清问题、定义、机制、必要推导、条件与结论。可以纯文字或包含公式，不要求每页都有图；标题克制，保留段落连接，避免把文章压成提纲或只列结论。先整理适合滑图阅读的正文，再在完整段落或推导边界分页，不机械截断原稿。

**辅助解释图**是默认图解类型，配合相邻正文页解释一个难以直接想象的关系，不承担整篇文章的介绍、推导和总结。

**一图流**只在明确要求总览、一图流或“一张图讲清整体内容”时启用，默认一张 3:4 图片。它组织整体故事，不等于塞入全部原文和公式；不因材料长而自动增加总览。

整篇稿件转图文时先列页序，注明正文页／辅助解释图、原文位置、讲解目标与制作方式。默认流程是“整理正文 → HTML 正文分页 → 在理解障碍处制作并插入辅助图 → 写发布摘要 → 检查完整图片序列”。不要求机械交替、固定页数或额外封面，首张正文页可直接开篇。制作两套时先完成并复用相同的 HTML 正文图片，保持页序一致，只比较辅助图的制作方式。

## 自动选点与数量

- **整篇稿件转图片组**：先保证正文页能独立串起主线，再默认选择两处价值高且互补的图解位置，把辅助图放在相关概念引入之后。正文页数随段落、公式与手机可读性确定，不用固定页数限制正文；没有两处有价值关系时不凑图。
- **仅给博客／长文配图**：默认直接制作两张互补的辅助解释图，注明插入位置，不制作整套正文图片。
- **指定局部概念或推导**：直接制作一张辅助解释图。
- **明确一图流／总览**：默认一张整体图，不额外附带两张辅助解释图。

用户已指定类型、数量、顺序或选点时遵从指定。简短展示页序或候选后直接制作，不把规划变成等待确认的关卡。HTML 分页按完整图意组织，不能只依靠自动切句决定图片内容；必要时每张图单独一个 Markdown 文件，按页序汇总 PNG。

## 辅助解释图

先确定关系，再选择最小且充分的构造：向量如何更新、分解或投影，长度／方向／角度怎样变化，不同作用如何竞争或抵消，约束如何影响位置，公式某项有什么几何意义。

主要面积留给对象、空间关系与变化过程。图中只保留变量和短标签，必要方向、角度、长度、约束、条件，以及与画面直接对应的少量公式。更新式可对应首尾相接箭头，投影式可对应垂线和投影向量；保留公式的依据是它与画面的关系，不追求覆盖率。

理解主线所需的连续推导和解释放进相邻的 HTML 正文页；其余扩展保留原稿。辅助解释图不设置长篇侧栏、推导流程区、总结卡片或底部结论条。图注简明易懂，用短句说明图中可见的动作或变化，让读者对着图就能理解；避免只罗列“已归一化”“共线”等术语，必要条件也用直观的说法表达。图形已说清的关系不再重复写一遍。

## 发布标题与配文

发布标题与封面标题不使用第一人称，直接点出主题、核心关系或结论，以准确清楚为先，避免自我叙事、夸张反差和故作悬念。封面尤其应把文章的核心论点放在主标题中，不仅写一个用于解释的概念或观察方式。配文采用作者第一人称，像分享自己的阅读笔记，轻松、自然、口语化，不写成论文摘要或交付说明，也不出现“用户提供的原稿”“本组共若干正文页”等制作视角的表述。

配文仍只作简短摘要：带出主题、核心问题和自己的理解，必要时自然引导看图；不逐页复述全文，不靠长配文补齐缺失正文。标题写入 `标题.txt`，配文写入 `配文.txt`，与最终 PNG、`预览.html` 一起放在 `output/<短名>/`；工作稿可另外保留。两种模式共用同一份标题与配文。来源和制作检查记录放在交付说明中，不混入可直接复制的配文。

验收时先不读摘要，按图片顺序检查概念、因果或推导连接和结论是否完整；需要依赖长配文才能看懂时，应补足正文页。

## 一图流

根据主题选择问题出发点、关键机制、必要推导、主要发现和核心结论，形成清楚阅读路径；不是每个主题都需要全部环节。允许多面板、短说明和必要公式，按解释价值分配面积，不强制等大卡片。

论文总览重点交代为什么研究、关键发现是什么、什么实验现象支持发现。优先将发现转为直观定性图形，例如对象加升降箭头；只有理解结论确需数值时才保留数据或完整图表，不补造幅度、速度和因果。

单张装不下时保留完整主线和必要条件，将细节移至正文；不能缩字硬塞或遗漏关键条件。用户指定一张时不自行扩成多图。
